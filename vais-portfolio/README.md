# VAIS — портфолио разработчика

Самостоятельный статический сайт-портфолио Ваисхона Маматова на HTML, CSS, Bootstrap 5 и Vanilla JavaScript. Сайт не является частью VEBORA Digital Studio и не требует Node.js или backend.

## Запуск локально

Можно открыть `index.html` напрямую в браузере. Для корректной проверки адреса страницы проекта запустите HTTP-сервер из папки `vais-portfolio`:

```powershell
py -m http.server 8000
```

Если Python Launcher недоступен, можно использовать любой локальный HTTP-сервер. Затем откройте `http://localhost:8000`. Внешние ресурсы Bootstrap загружаются с jsDelivr, поэтому для них нужно подключение к интернету.

## Настройка сайта

Иллюстративные превью проектов находятся в `assets/images/preview-*.svg` и показываются в карточках и на странице подробностей. Это визуальные макеты, а не реальные снимки страниц; для настоящих скриншотов замените эти файлы и оставьте атрибуты `preview` и `previewAltKey` в `js/projects.js`.


- Контакты: откройте `js/config.js` и укажите Telegram username (например, `@username`), ссылку или username GitHub, email. Пустые поля не отображаются. Секреты сюда добавлять нельзя.
- Проекты: редактируйте единый массив в `js/projects.js`. Используйте уникальный `id`, `category` (`web`, `bots`, `experiments`), `status` (`completed`, `development`, `concept`), `type`, локализованное `title` либо ключ перевода и соответствующие ключи описания. Рабочие ссылки добавляйте только при наличии.
- Переводы: добавьте одинаковый ключ в объекты `ru` и `en` в `js/translations.js`. Атрибуты `data-i18n` используют эти ключи.
- Цвета: измените CSS-переменные в начале `css/style.css`; тема может переопределять их через `data-theme="light"`.

Для новых функций карточек редактируйте шаблон в `js/main.js`; подробная страница `project.html?id=ID` автоматически получает запись из массива. Данные вставляются как текстовые узлы.

## Проверка

Проверьте переключатели языка и темы, фильтры проектов, карточку подробностей, ссылки и копирование Telegram. Измените ширину окна до 320, 375, 390, 768, 1024 и 1440 px, проверьте клавиатурную навигацию (Tab/Enter) и режим уменьшения движения. После публикации проверьте URL сайта, изображения, метаданные и валидность HTML. `localStorage` используется по возможности; без него выбор просто не сохранится.

## Публикация на GitHub Pages

1. Создайте репозиторий и поместите в его корень содержимое этой папки.
2. В настройках репозитория откройте **Pages**, выберите публикацию из нужной ветки и корневой папки.
3. Дождитесь сборки GitHub Pages и откройте выданный URL.
4. Если сайт опубликован не в корне домена, обновите пути к ресурсам и навигации в HTML.

## Публикация на Cloudflare Pages

Создайте Pages-проект, загрузите содержимое папки или подключите репозиторий. Для статического размещения без сборщика укажите корень проекта и оставьте команду сборки пустой; каталог вывода — корень (`/`). После публикации проверьте выданный адрес.

## Домен и SEO после публикации

В панели выбранного хостинга добавьте домен и следуйте её актуальным DNS-инструкциям; включите HTTPS. После того как постоянный URL известен:

1. Добавьте canonical в `<head>` обеих страниц с правильными абсолютными URL. Для `project.html` учитывайте параметр `id` либо выберите канонический URL согласно принятой схеме.
2. Обновите `sitemap.xml` реальными URL главной и страницы проекта и укажите его в `robots.txt`.
3. Укажите реальный URL в JSON-LD `Person.url`, если он подходит, и добавьте `og:url`.
4. Обновите Open Graph изображение только если добавите собственную оптимизированную картинку.
5. Проверьте тексты, статус проектов, контакты и метаданные. Адрес VEBORA нельзя использовать как canonical личного сайта.

## Что подтвердить и заполнить

- Telegram, GitHub и email (если хотите показывать email).
- Реальные детали реализации VEBORA — состав функций и технологий можно уточнить в `js/projects.js`.
- Ссылки на репозитории проектов, когда они появятся.
- Адрес публикации для canonical, sitemap и JSON-LD.
